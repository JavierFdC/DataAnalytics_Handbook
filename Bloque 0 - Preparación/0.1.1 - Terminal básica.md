## 3. ¿Qué es la terminal y qué no es?

La **terminal** es una ventana donde damos órdenes al ordenador **escribiendo texto** en lugar de hacer clic. Escribimos un comando, pulsamos Enter, el ordenador lo ejecuta y nos responde con texto.

Conviene distinguir tres palabras que se usan casi como sinónimos:

**Terminal (o emulador de terminal).** La ventana en sí: el programa que muestra el texto y recoge lo que tecleamos. En Windows, *Windows Terminal*; en macOS, la app *Terminal* o alternativas como iTerm2.

**Shell.** El programa que vive dentro de la terminal e **interpreta** lo que escribimos. En Windows usaremos **PowerShell**; en macOS el shell por defecto es **zsh**; en Linux suele ser **bash**. Cada shell tiene su propio lenguaje, aunque los comandos básicos se parecen mucho.

**Línea de comandos (CLI, *Command Line Interface*).** La forma de trabajar: interactuar con programas mediante comandos de texto, en oposición a la interfaz gráfica (GUI) de ventanas y botones.

### Por qué la necesita un analista de datos

Es legítimo preguntarse para qué aprender a escribir comandos si el explorador de archivos funciona perfectamente. Hay cuatro razones concretas en este curso:

1. **Hay herramientas que solo tienen versión de terminal.** Git, pip (el instalador de librerías de Python) y `psql` (el cliente de PostgreSQL) se usan escribiendo comandos.
2. **Los mensajes de error aparecen en la terminal.** Cuando una instalación falla, la pista está en el texto que devuelve la terminal. Saber leerlo ahorra horas.
3. **Lo que se escribe se puede repetir y automatizar.** Una secuencia de clics no se puede guardar; una secuencia de comandos, sí. Es la base de los procesos ETL automatizados.
4. **Los servidores no tienen ratón.** Cuando trabajemos con máquinas en la nube a menudo la única forma de entrar será una terminal remota.

### Comparación con lo que ya conocemos

**Terminal vs explorador de archivos.** Hacen muchas cosas iguales: navegar por carpetas, crear, mover y borrar archivos. El explorador es más cómodo para tareas puntuales y visuales. La terminal es más rápida para tareas repetitivas, más precisa (no hay arrastres accidentales) y es la única vía para lanzar ciertos programas. No compiten: usaremos los dos.

### La frase clave

> La terminal no es una herramienta de programadores: es la forma más directa de hablar con el ordenador. No hace falta memorizar cien comandos; con quince bien entendidos tenemos el 95 % del trabajo cubierto.

## 4. Abrir la terminal

### Windows

Windows 11 incluye **Windows Terminal**, que por defecto abre **PowerShell**. Para abrirla:

- Pulsamos la tecla **Windows**, escribimos `terminal` y pulsamos Enter.
- O bien, clic derecho sobre el botón de Inicio → **Terminal**.

En Windows 10, si no tenemos Windows Terminal, lo instalamos gratis desde la Microsoft Store o, mientras tanto, abrimos directamente **PowerShell** desde el menú Inicio. Todo lo que hagamos en esta sesión funciona igual.

> Windows tiene además el antiguo **Símbolo del sistema** (`cmd.exe`). No lo usaremos: sus comandos son distintos y está en desuso. Si al abrir la terminal vemos una ventana negra con `C:\Users\...>` sin la palabra `PS` delante, estamos en `cmd` y no en PowerShell.

### macOS

Abrimos **Spotlight** con `Cmd + Espacio`, escribimos `terminal` y pulsamos Enter. También está en **Aplicaciones > Utilidades > Terminal**. El shell por defecto desde macOS Catalina es **zsh**.

### Linux

Normalmente `Ctrl + Alt + T`, o buscando "Terminal" en el menú de aplicaciones. El shell habitual es **bash**. Los comandos de esta sesión son los mismos que en macOS.

### Primer arranque: anatomía del *prompt*

Al abrir la terminal vemos una línea parecida a una de estas:

```
PS C:\Users\javier>                  ← Windows (PowerShell)
javier@MacBook-Air ~ %               ← macOS (zsh)
javier@portatil:~$                   ← Linux (bash)
```

Esa línea es el **prompt**: la terminal nos dice "estoy lista, escribe". Contiene información útil:

- En PowerShell, `PS` indica el shell y `C:\Users\javier` es la **carpeta en la que estamos ahora mismo**.
- En macOS y Linux, `javier` es el usuario, `MacBook-Air` el nombre del equipo, y `~` la carpeta actual (`~` es la abreviatura de nuestra carpeta personal).
- El símbolo final (`>`, `%`, `$`) marca dónde empieza lo que escribimos nosotros.

En los ejemplos de esta guía **no copiamos el prompt**: solo lo que va detrás.

## 5. Rutas: la dirección de cada archivo

Todo archivo del ordenador tiene una **ruta** (*path*): la secuencia de carpetas que hay que recorrer desde la raíz hasta llegar a él.

```
Windows:  C:\Users\javier\proyectos\mi-portfolio-data-analytics\README.md
macOS:    /Users/javier/proyectos/mi-portfolio-data-analytics/README.md
Linux:    /home/javier/proyectos/mi-portfolio-data-analytics/README.md
```

Dos diferencias saltan a la vista: Windows empieza por una letra de unidad (`C:`) y separa carpetas con **barra invertida** `\`; macOS y Linux empiezan en `/` (la raíz) y separan con **barra normal** `/`. PowerShell acepta las dos barras, así que en esta guía usaremos `/` siempre que se pueda: es la que entienden todos los sistemas, Git, Python y las URLs.

### Rutas absolutas y relativas

**Ruta absoluta.** Empieza en la raíz y funciona desde cualquier sitio: `C:\Users\javier\proyectos` o `/Users/javier/proyectos`.

**Ruta relativa.** Se interpreta **desde la carpeta en la que estamos**. Si estamos en `/Users/javier`, la ruta relativa `proyectos/mi-portfolio-data-analytics` apunta a `/Users/javier/proyectos/mi-portfolio-data-analytics`.

Tres atajos que usaremos constantemente:

| Símbolo | Significado | Ejemplo |
|---|---|---|
| `~` | Nuestra carpeta personal | `cd ~` nos lleva a casa desde cualquier sitio |
| `.` | La carpeta actual | `code .` abre la carpeta actual en VS Code (sesión 3) |
| `..` | La carpeta padre (un nivel arriba) | `cd ..` sube un nivel |

### Analogía

Una ruta absoluta es una dirección postal completa: "Calle Mayor 12, 3.º B, Madrid". Una ruta relativa son indicaciones desde donde estamos: "sube una planta y es la segunda puerta". Las dos llevan al mismo sitio, pero la relativa solo funciona si sabemos dónde estamos. Por eso el comando más importante de la terminal es el que nos dice dónde estamos.

### Nombres con espacios

La terminal usa los espacios para separar un comando de sus argumentos. Si una carpeta se llama `Mis documentos`, el comando `cd Mis documentos` se interpreta como "ve a `Mis` con un argumento extra `documentos`" y falla. Hay que usar comillas: `cd "Mis documentos"`.

Por eso, para archivos y carpetas de trabajo, **adoptamos una convención sin espacios, sin tildes y en minúsculas**: `mi-portfolio-data-analytics`, `verificar_entorno.py`. Nos ahorrará problemas con Git, Python y los servidores.

## 6. Los comandos esenciales

Esta tabla es la chuleta de la sesión. En la mayoría de casos el comando es idéntico en PowerShell y en zsh/bash, porque PowerShell define **alias** con los nombres clásicos de Unix.

| Qué queremos hacer | PowerShell (Windows) | zsh / bash (macOS, Linux) |
|---|---|---|
| Ver en qué carpeta estamos | `pwd` | `pwd` |
| Listar el contenido | `ls` | `ls` |
| Listar incluidos los ocultos | `ls -Force` | `ls -a` |
| Entrar en una carpeta | `cd nombre` | `cd nombre` |
| Subir un nivel | `cd ..` | `cd ..` |
| Ir a la carpeta personal | `cd ~` | `cd ~` (o solo `cd`) |
| Crear una carpeta | `mkdir nombre` | `mkdir nombre` |
| Crear un archivo vacío | `ni archivo.txt` | `touch archivo.txt` |
| Ver el contenido de un archivo | `cat archivo.txt` | `cat archivo.txt` |
| Copiar | `cp origen destino` | `cp origen destino` |
| Mover o renombrar | `mv origen destino` | `mv origen destino` |
| Borrar un archivo | `rm archivo.txt` | `rm archivo.txt` |
| Borrar una carpeta con todo su contenido | `rm -r carpeta` | `rm -r carpeta` |
| Abrir un archivo con el editor de texto | `notepad archivo.txt` | `open -e archivo.txt` (macOS) |
| Abrir la carpeta actual en el explorador | `explorer .` | `open .` (macOS) |
| Limpiar la pantalla | `clear` o `Ctrl + L` | `clear` o `Ctrl + L` |

> **Cuidado con `rm`.** Lo que se borra desde la terminal **no pasa por la papelera**. Desaparece. Antes de un `rm -r`, un `pwd` y un `ls` para confirmar dónde estamos y qué vamos a borrar.

### Tres trucos que cambian la experiencia

**Autocompletado con Tab.** Escribimos las primeras letras de una carpeta o archivo y pulsamos `Tab`: la terminal completa el nombre. Si hay varias opciones, pulsando `Tab` otra vez las recorre (PowerShell) o las lista (zsh). Es más rápido y **evita errores de escritura**. La regla de los profesionales: nunca escribir un nombre entero si Tab puede hacerlo.

**Historial con las flechas.** `↑` recupera el comando anterior; pulsando varias veces recorremos el historial. Ideal para repetir o corregir un comando largo.

**Cancelar con `Ctrl + C`.** Si un comando se queda colgado o nos hemos equivocado a mitad de escribir, `Ctrl + C` lo interrumpe y nos devuelve el prompt. En la terminal, `Ctrl + C` **no es copiar** (para copiar: seleccionar con el ratón y `Ctrl + Shift + C` en Windows Terminal, o `Cmd + C` en macOS).

## 7. Construcción del portfolio paso a paso

Vamos a crear la estructura inicial de nuestro repositorio. Escribimos los comandos uno a uno y, después de cada uno, **miramos qué ha pasado** antes de seguir.

### Paso 1: situarnos en la carpeta personal

```powershell
cd ~
pwd
```

`pwd` nos confirma la ruta: `C:\Users\<usuario>` en Windows o `/Users/<usuario>` en macOS.

> **Dónde NO crear el repositorio.** Evitamos las carpetas sincronizadas con la nube: OneDrive (en Windows, a menudo `Documentos` y `Escritorio` lo están sin que lo sepamos), Google Drive, Dropbox o iCloud. Git y los entornos virtuales de Python generan miles de archivos pequeños que se modifican a la vez, y el sincronizador puede corromperlos o generar copias en conflicto. GitHub ya será nuestra copia en la nube.

### Paso 2: crear una carpeta para todos nuestros proyectos

```powershell
mkdir proyectos
cd proyectos
```

A partir de ahora, cada proyecto del curso vivirá dentro de `~/proyectos`.

### Paso 3: crear el repositorio y sus subcarpetas

```powershell
mkdir mi-portfolio-data-analytics
cd mi-portfolio-data-analytics
mkdir notas
mkdir practicas
```

Comprobamos con `ls`. Deberíamos ver las dos carpetas.

### Paso 4: crear los primeros archivos vacíos

En Windows (PowerShell):

```powershell
ni README.md
ni notas/terminal.md
```

En macOS y Linux:

```bash
touch README.md
touch notas/terminal.md
```

Fijémonos en que `notas/terminal.md` es una **ruta relativa**: hemos creado un archivo dentro de la subcarpeta `notas` sin necesidad de entrar en ella.

### Paso 5: escribir nuestra chuleta de comandos

Abrimos el archivo con el editor de texto del sistema **desde la propia terminal**:

```powershell
notepad notas/terminal.md        # Windows
```

```bash
open -e notas/terminal.md        # macOS
```

Escribimos en él, con nuestras propias palabras, los comandos que hemos aprendido hoy y para qué sirve cada uno. Por ejemplo:

```
# Chuleta de terminal

pwd        -> dónde estoy
ls         -> qué hay aquí
cd carpeta -> entrar en una carpeta
cd ..      -> subir un nivel
mkdir x    -> crear carpeta
...
```

Guardamos y cerramos. En la sesión 4 aprenderemos a darle formato con Markdown; de momento, texto plano.

### Paso 6: comprobar el resultado

```powershell
cat notas/terminal.md
ls -Recurse          # Windows: lista todo el árbol de carpetas
```

```bash
cat notas/terminal.md
ls -R                # macOS / Linux
```

Deberíamos ver nuestras dos carpetas, el `README.md` vacío y la chuleta con su contenido.

### Paso 7: practicar mover, copiar y borrar

Para perder el miedo, hacemos una prueba controlada dentro de `practicas`:

```powershell
cd practicas
mkdir prueba
cp ../notas/terminal.md prueba/copia.md
mv prueba/copia.md prueba/renombrado.md
ls prueba
rm -r prueba
ls
cd ..
```

Leamos la tercera línea con calma: `../notas/terminal.md` significa "sube un nivel, entra en `notas` y coge `terminal.md`". Con copiar, renombrar y borrar dominados, ya sabemos hacer desde la terminal todo lo que hacíamos con el explorador.

## 8. La variable PATH: por qué "no se reconoce como comando"

Hay un concepto que no es imprescindible hoy pero que explica **la mitad de los problemas de instalación** que tendremos en las sesiones siguientes. Merece la pena entenderlo ahora.

Cuando escribimos `git` o `python`, la terminal no busca en todo el disco: busca en una lista concreta de carpetas guardada en una **variable de entorno** llamada `PATH`. Si el programa está en una de esas carpetas, lo encuentra y lo ejecuta. Si no, responde con un error:

```
git : El término 'git' no se reconoce como nombre de un cmdlet, función,
archivo de script o programa ejecutable.            ← PowerShell

zsh: command not found: git                          ← macOS
```

Ese mensaje casi nunca significa "el programa no está instalado". Suele significar "está instalado, pero su carpeta no está en el PATH" o "la terminal se abrió antes de instalarlo".

### Ver el PATH

```powershell
$env:Path -split ';'              # Windows: una carpeta por línea
```

```bash
echo $PATH | tr ':' '\n'          # macOS / Linux: una carpeta por línea
```

### Averiguar qué programa se está ejecutando

```powershell
where.exe notepad                 # Windows
```

```bash
which ls                          # macOS / Linux
```

Nos dice la ruta completa del ejecutable que la terminal encontraría. Usaremos este comando en la sesión 5 para comprobar que estamos usando el Python correcto.

### La regla de oro de las instalaciones

> Después de instalar un programa, **cerramos la terminal y abrimos una nueva**. La terminal lee el PATH al arrancar; una ventana abierta antes de la instalación no actualiza los cambios.

## 9. Lo que la terminal ha hecho por debajo

Cuando escribimos `mkdir notas` y pulsamos Enter, ocurren tres cosas:

1. **El shell trocea la línea** en palabras separadas por espacios: el comando (`mkdir`) y sus argumentos (`notas`). Por eso los espacios en los nombres dan problemas.
2. **Busca el comando.** Primero mira si es un comando interno o un alias del propio shell; si no, lo busca en las carpetas del `PATH`.
3. **Lo ejecuta en la carpeta actual.** Las rutas relativas que le pasemos se interpretan desde ahí.

En PowerShell hay un matiz interesante. `ls`, `cp`, `mv`, `rm` o `cat` no son programas reales, sino **alias** que PowerShell ha definido para que nos sintamos como en casa. Podemos comprobarlo:

```powershell
Get-Alias ls
```

```
CommandType     Name                  Definition
-----------     ----                  ----------
Alias           ls -> Get-ChildItem
```

El comando real es `Get-ChildItem`. PowerShell usa nombres largos con el patrón *Verbo-Sustantivo* (`Get-ChildItem`, `New-Item`, `Remove-Item`), pensados para que se lean como frases. Los alias existen para escribir menos. Por eso algunas opciones cambian entre sistemas: `ls -a` es de Unix y en PowerShell se escribe `ls -Force`.

## 10. Errores comunes y troubleshooting

**1. "No se encuentra la ruta de acceso" / "No such file or directory".** La ruta no existe **desde donde estamos**. Hacemos `pwd` para ver dónde estamos y `ls` para ver qué hay. Nueve de cada diez veces es una ruta relativa escrita desde la carpeta equivocada o un error tipográfico que el `Tab` habría evitado.

**2. "cd Mis documentos" no funciona.** Espacios en el nombre. Comillas: `cd "Mis documentos"`. O mejor, `Tab` para autocompletar: la terminal añade las comillas sola.

**3. En Windows, `touch` no existe.** Es un comando de Unix sin alias en PowerShell. Usamos `ni archivo` (alias de `New-Item`).

**4. En Windows, `mkdir -p a/b/c` falla o hace algo raro.** `-p` es una opción de Unix. En PowerShell, `mkdir a/b/c` ya crea las carpetas intermedias sin opciones extra.

**5. Los archivos creados con `echo "texto" > archivo.txt` se ven con caracteres extraños.** En Windows PowerShell 5.1 (la versión que trae Windows por defecto), la redirección `>` guarda el archivo en codificación UTF-16, que Git y muchos programas interpretan mal. Para crear archivos con contenido, usamos un editor (`notepad`, y desde la sesión 3, VS Code). En macOS y Linux no hay este problema.

**6. "Me he perdido y no sé dónde estoy."** `cd ~` nos devuelve a la carpeta personal desde cualquier sitio. Desde ahí, `cd proyectos/mi-portfolio-data-analytics`.

**7. La terminal se ha quedado "colgada" y no responde.** Probablemente hay un comando en ejecución esperando algo. `Ctrl + C` lo interrumpe. Si el prompt muestra `>>` en PowerShell, hemos abierto unas comillas sin cerrarlas: `Ctrl + C` y a empezar.

## 12. Para profundizar

Esta sección va más allá de lo necesario para el curso. Es material para quien quiera ir un paso más allá.

### Tuberías y redirecciones

La verdadera potencia de la terminal aparece al **encadenar comandos**. La tubería `|` pasa la salida de un comando como entrada del siguiente, y `>` la guarda en un archivo:

```bash
# macOS / Linux: las 5 primeras líneas de un CSV
head -n 5 ventas.csv

# cuántas filas tiene un CSV
wc -l ventas.csv

# qué líneas contienen la palabra "Madrid"
grep "Madrid" ventas.csv
```

```powershell
# PowerShell: equivalentes
Get-Content ventas.csv -TotalCount 5
(Get-Content ventas.csv).Count
Select-String "Madrid" ventas.csv
```

Para un analista, estos tres comandos son una forma rapidísima de echar un vistazo a un CSV de varios gigas que Excel no podría abrir.

### PowerShell trabaja con objetos, no con texto

En bash, lo que viaja por la tubería es texto. En PowerShell viajan **objetos** con propiedades, lo que permite cosas como ordenar archivos por tamaño sin procesar texto:

```powershell
ls | Sort-Object Length -Descending | Select-Object -First 5 Name, Length
```

### PowerShell 7

Windows trae **Windows PowerShell 5.1**. Existe una versión moderna, **PowerShell 7**, multiplataforma y con mejoras (entre ellas, UTF-8 por defecto al redirigir). Se instala gratis desde la Microsoft Store o con `winget install --id Microsoft.PowerShell -e`. Para el curso, la 5.1 es suficiente.

### Git Bash y WSL

Al instalar Git en la próxima sesión, en Windows aparecerá también **Git Bash**, una terminal con bash que acepta los comandos de Unix (`touch`, `ls -a`, `grep`...). Y para quien quiera un Linux completo dentro de Windows existe **WSL** (*Windows Subsystem for Linux*). Ninguno de los dos es necesario en el curso.

### Scripts

Un archivo con una secuencia de comandos es un **script**: `.ps1` en PowerShell, `.sh` en bash. Es el primer paso hacia la automatización que veremos con Python en el bloque 3.
